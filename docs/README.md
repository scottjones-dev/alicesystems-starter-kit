# @repo/development-docs

The template's own developer documentation: how the monorepo is put together and the decisions behind each package. It is for the people working in this repo.

This is **not** the docs for a product built on the template. That is [`apps/docs`](../apps/docs/README.md) (port 4000).

## Why it exists

Each package and app has a page explaining what it is, why it exists and its trade-offs. Keeping them in a searchable site (Fumadocs on Next.js, set up with `create-fumadocs-app`) means they stay readable as the template grows, and they can later describe what a generator will create for each part.

## Run it

```bash
pnpm --filter @repo/development-docs dev          # http://localhost:1000
pnpm --filter @repo/development-docs build
pnpm --filter @repo/development-docs types:check
pnpm --filter @repo/development-docs lint
pnpm --filter @repo/development-docs test
```

`next dev` also writes `AGENTS.md` and `CLAUDE.md` into this folder. They are generated by Next.js.

Write pages in `content/docs/**/*.mdx` and order them with a `meta.json` in the same folder.

## Languages

The docs use the template's languages (`app.i18n` in `@repo/config`: English, Spanish, German, French, Portuguese, Chinese), so there is one list. Every URL starts with the language: `/en/docs/...`, `/es/docs/...`. A URL without one is redirected using the browser's language.

Today only English has content. A page with no translation falls back to English, so a language can be added one page at a time.

**To translate a page**, add a file with the language in its name next to it: `content/docs/faq.es.mdx` next to `faq.mdx`. To translate a folder's title and page order, add `meta.es.json` next to `meta.json`.

**Not translated yet:**
- The landing page text (`app/[lang]/(home)/page.tsx`) is English in every language.
- Fumadocs' own interface text (search box, "Next page", ...) is English except each language's name in the switcher. Add strings in `translations` in `lib/layout.shared.tsx`.
- The "Docs" in the breadcrumb.

**Links in content:** write them as `/docs/packages/db`, with no language. `LocalizedAnchor` and `LocalizedCard` (in `components/mdx.tsx`) add the reader's. Relative file links (`./other.mdx`) are not supported, because those components replace Fumadocs' relative-link helper.

## Search engines

- **Set `DOCS_SITE_URL`** to the public address (`https://docs.example.com`, no path) wherever the site is built. It sets `metadataBase`, so canonical links, the sitemap and social images use the real address. In development it falls back to `http://localhost:1000`. A production build without it **fails on purpose**, so a sitemap full of localhost links never ships. A build that is only checking the code can set `SKIP_ENV_VALIDATION=1`. It is listed in this package's `turbo.json`, so Turborepo passes it to the build and rebuilds when it changes. (It is not yet in `env.registry.ts`, which covers the apps and packages that use `@repo/env`; this site does not.)
- **Titles** read "Page title | StarterKit Docs", set by the title template in `app/[lang]/layout.tsx`.
- **Languages.** Fumadocs creates a page for every language, even when only English has the file, so six identical pages would compete. `lib/seo.ts` tells a real translation (it has its own file, such as `faq.es.mdx`) from a copy. A real translation is its own canonical and is listed in the sitemap, each with `hreflang` links to the others and `x-default` for English. A copy has its canonical link pointed at the English page and is left out of the sitemap. The home page text is English in every language, so each language's home page names `/en` as the original.
- **`robots.txt`** allows everything except `/api/` and links the sitemap. The 404 pages are `noindex`.

## 404 pages

A missing docs page (`/en/docs/nope`) and a language that does not exist (`/xx/docs`) show the 404 page inside the site. A URL that matches no route (`/en/nope`) uses `app/global-not-found.tsx`. That file is needed because the root layout sits under the `[lang]` segment, and it relies on Next.js' experimental `globalNotFound` flag (set in `next.config.mjs`). If that flag changes in a Next.js update, this is the place to look.

## GitHub links

`gitConfig` in `lib/shared.ts` says where the source lives (`scottjones-dev/alicesystems-starter-kit`, branch `master`). The header icon links to the repo, and each page's "View options" menu links to that page's file through `getPageGithubUrl`. `contentPath` (`docs/content/docs`) is the pages' folder from the repo root, because this site is one workspace in a monorepo. Change it if the folder moves, or the links will 404.

## Colours

The site uses the shared `@repo/ui` stylesheet, so it gets the same Tailwind setup as the other apps. The template's shared theme is a neutral placeholder, so `app/brand-theme.css` overrides it with the "Midnight Sanctuary" palette copied from the starter-kit repo (`packages/ui/src/styles/theme.css`). It is loaded after the shared stylesheet so its values win, and it affects this site only.

The values are copied by hand and will not follow later changes in starter-kit. To make the whole template use this palette, edit `packages/config/src/theme.ts` and run `pnpm theme:generate`, then delete `brand-theme.css`.

## Breadcrumb

Fumadocs' built-in breadcrumb starts at the first folder. `DocsBreadcrumb` adds a "Docs" link (to the reader's language) at the front ("Docs › Packages") and leaves out the current page, since its title is right below. It shows nothing on the docs home. It is passed to the page through `slots={{ breadcrumb: DocsBreadcrumb }}`.

## Tests

`pnpm test` (Vitest) covers `localizeHref`, `getPageGithubUrl`, `getSiteUrl` and the language rules in `lib/seo.ts`, the logic here. The rest is content and presentational glue, checked by `types:check` and `lint` (Biome, via Ultracite).

## Depends on / used by

- Depends on `@repo/ui` (shared stylesheet and theme setup) and `@repo/config`. Both are compiled with the app (`transpilePackages` in `next.config.mjs`).
- Nothing depends on this package.
