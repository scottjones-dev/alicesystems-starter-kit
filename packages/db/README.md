# @repo/db

Database layer: Drizzle ORM on PostgreSQL (node-postgres).

## Why it exists

Only the API talks to Postgres. This package owns the client, the column helpers, the migrations and the test helper, so the data model lives in one place. The reasoning is in [`docs/content/docs/db.md`](../../docs/content/docs/db.md).

Its first table is `audit_log` (behaviour in [`@repo/audit`](../audit/README.md)); auth's arrive with auth, and each platform adds its own.

## What's inside

```
src/
  client.ts      db (Pool + drizzle), pingDatabase(), closeDb()
  columns.ts     id() (UUIDv7), createdAt(), updatedAt() (timestamptz)
  checks.ts      oneOf(): a CHECK constraint for enum-like text columns
  keys.ts        DATABASE_URL, defined once for @repo/env
  testing.ts     createTestDatabase(): a throwaway database with the real migrations
  schemas/       your tables, one file each (drizzle-kit reads this folder)
migrations/      generated by drizzle-kit
drizzle.config.ts
```

Tables use `snake_case` columns and `uuidv7()` ids (Postgres 18). Enum-like columns are `text` with a CHECK constraint named `<table>_<column>_valid`, so Postgres itself refuses a bad value from any writer.

## Use it

```ts
import { db } from "@repo/db/client";
import { widget } from "@repo/db/schemas/widget"; // after you add it

const rows = await db.select().from(widget);
```

### Add a table

1. Create `src/schemas/<name>.ts` with `pgTable`, starting from `id()`, `createdAt()` and `updatedAt()`, and use `oneOf()` for fixed-value columns.
2. Add `"./schemas/*": "./src/schemas/*.ts"` to this package's `exports` the first time.
3. `pnpm db:generate`, read the generated SQL, then `pnpm db:migrate`.
4. Add a block for it in `src/db.integration.test.ts` (or, for a package's own table, an integration test in that package using `createTestDatabase`).

Something Drizzle cannot describe (a trigger, a function) goes in a hand-written migration made with `pnpm exec drizzle-kit generate --custom --name=<what>`; `audit_log_append_only` is an example.

## Run it

Postgres runs in Docker: `pnpm infra:postgres:up` (see [`infra/postgres`](../../infra/postgres/README.md)). Every command reads `DATABASE_URL` from the root `.env`, written by `pnpm setup:local` (local Docker) or `pnpm env:pull <env>` (Infisical). Variables already set in the shell win, so CI passes them directly.

| Command (repo root) | Does |
| --- | --- |
| `pnpm db:generate` | create a migration from schema changes |
| `pnpm db:migrate` | apply migrations |
| `pnpm db:check` | check the migration history is consistent |
| `pnpm db:push` | push the schema directly (throwaway dev use) |
| `pnpm db:studio` | Drizzle Studio |
| `pnpm test:integration` | integration tests against the local Postgres |

## Connection pool

`src/client.ts` keeps one pool of up to 10 connections, with a 5 s connect timeout, 30 s idle timeout and 15 s statement timeout, so a stuck database fails a request fast instead of hanging everything. A dropped idle connection is logged and replaced instead of crashing the process. `pingDatabase()` gives a readiness endpoint a 2 s probe.

## Tests

- `pnpm --filter @repo/db test`: unit tests (no database). The column helpers, `oneOf` (including the SQL it writes into a migration, and quote escaping) and the `createTestDatabase` prefix check.
- `pnpm test:integration` (after `pnpm infra:postgres:up` and `pnpm setup:local`): builds a table from the helpers, turns it into SQL the way `drizzle-kit generate` does, applies it to a throwaway database on Postgres 18, and checks UUIDv7 ids, timestamptz columns, the CHECK constraint, and `pingDatabase`.

## Design notes

- **`pg`, not a serverless HTTP driver.** The HTTP drivers cannot run multi-statement transactions, which money handling needs.
- **`oneOf` writes literals, not parameters.** On the stable Drizzle line, drizzle-kit wrote the values as `$1, $2` in the migration, which Postgres rejects. The integration test caught it.
- **Stable Drizzle `0.45.x`.** The v1 line is still beta/rc. Revisit when it is stable.
- **Integrity in the database.** Foreign keys, CHECKs and unique keys hold for every writer, now and later.

## Depends on / used by

Depends on `@repo/env`, `drizzle-orm`, `pg`, `zod`, and `drizzle-kit` for migrations. Used by the API app, by `@repo/audit` (which reads and writes the `audit_log` table) and by auth (not built yet).
